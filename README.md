# 貯蔵品購入申請アプリ

Google Apps Script（GAS）で動作する、貯蔵品購入申請のデジタル申請アプリです。

UIはリデザイン案「B案 ゆとり」（藍ベース・余白広め・カードUI・縦タイムライン承認フロー）で確定しています。

## 構成

- フロントエンド: HtmlService + HTML/CSS/vanilla JavaScript（リデザイン B案「ゆとり」）
- サーバー: Apps Script V8
- データ保存: Google Spreadsheet
- PDF保存: Google Drive（モノクロA4の申請書フォーマット）
- 通知: MailApp

## 画面構成

ナビは **新規申請 / 差戻しプール / 上席承認待ち / 金額入力待ち / 総務部長承認待ち / 社長承認待ち / 手配待ち / 全申請 / 管理** の9タブです（「管理」のみ管理者に表示）。進捗確認のため一覧は全員が閲覧でき、承認・金額入力などの操作可否は別途制御されます。

- 新規申請: 明細を行カードで入力。品目ごとに単位（個・本・ケース・セット等のプルダウン、または「その他」で自由入力）を指定します。金額は購買が見積ステップで単位あたりの税抜単価を入力して確定し、しきい値超で社長決裁ルートを表示。
- 明細の修正: 購買が金額を確定するまでは、提出後でも品名・型式・数量・単位などを修正できます（承認の流れは維持され、変更内容は履歴に残り現在の承認者へ通知されます）。
- 差戻しプール: 差戻し中の申請を全員で共有し、誰でも編集・再提出・削除できます。
- 社長承認待ち: 社長決裁待ちの案件一覧。行から直接「社長決裁モード」を起動できます。
- 詳細: 縦タイムラインの承認フロー、申請書PDFプレビュー、明細、承認履歴を表示。

## 明細ごとの承認と部分差戻し

承認パネル・見積パネルの明細一覧はチェックボックス付きで、既定は全件承認です。差し戻したい明細のチェックを外して実行すると、**その明細だけが新しい申請としてコピーされて差戻しプールへ移り、残りの明細はそのまま次のステップへ進みます**（申請書が1枚から2枚に分離するイメージ）。

- 対応ステップ: 上席 / 購買見積 / 総務部長 / 社長（購買手配は既に発注段階のため不可）
- 分離された申請は通常の差戻し済み申請と同じで、プールで編集・再提出・削除できます。再提出すると上席から通常フローが始まります。
- 金額確定後（総務部長・社長）の分割では、合計額が下がっても承認経路は変えません（社長決裁ルートは維持）。金額が増えることはないため、必要な承認が飛ばされることはありません。
- 購買見積での分割は、金額をここで初めて確定させる工程のため、**残った明細の合計でしきい値を判定して経路を組み直します**（高額な明細を分離して10万円未満になれば社長決裁は付きません）。
- 全明細の選択解除はできません（申請全体の差戻しをご利用ください）。
- 全画面（社長決裁）モードは従来どおり全体承認・全体差戻しのみです。

## 社長決裁モード（タブレット提示）

社長決裁ステップの案件で、総務部長（管理者）がタブレットを持参して社長へ提示し、その場で承認・差戻しを記録する全画面モードです。

- 申請書をA4縦の比率を保ったまま画面にフィット表示（決裁欄・履歴・バーコードを省いた絞り込みプレビュー）。
- 下部の大型ボタンで「承認する / 差し戻す」をその場で記録。差戻しは理由チップ＋コメントで素早く入力。
- 承認記録は社長名義で残し、代理操作した担当者名をコメントに併記します（`recordPresidentDecision`）。

## 初期セットアップ

1. Google Apps Scriptで新規プロジェクトを作成します。
2. `.clasp.json.example` を `.clasp.json` にコピーし、`scriptId` を作成したGASプロジェクトIDへ変更します。
3. 依存関係を入れてGASへ反映します。

```powershell
npm install
npm run push
```

4. Apps Scriptエディタで `setupApplication()` を1回実行します。
5. Webアプリとしてデプロイします。
   - 実行ユーザー: 自分
   - アクセスできるユーザー: ドメイン内のユーザー
6. 初回アクセス後、管理画面で以下を設定します。
   - 管理者メールアドレス
   - 承認者マスタ
   - 社長決裁しきい値（初期値: 100000）
   - PDF保存先フォルダID（空欄なら自動作成）

初期管理者は `imaizumi@lineworks-local.info` です。変更する場合は `Constants.gs` の `adminEmails` 初期値、または管理画面の管理者メールアドレスを更新してください。

管理者メールアドレスを空欄にした場合は、初期設定のため全ユーザーを管理者として扱います。運用開始前に必ず管理者を設定してください。

## 承認フロー

- 税抜10万円未満: 申請者 → 上席 → 購買（見積・金額入力）→ 総務部長 → 購買（手配）→ 完了
- 税抜10万円以上: 申請者 → 上席 → 購買（見積・金額入力）→ 総務部長 → 社長 → 購買（手配）→ 完了

申請時は金額を入力しません。購買が見積ステップで各明細の税抜単価を入力した時点で合計が確定し、社長決裁しきい値（税抜）以上なら社長決裁が経路へ追加されます。

- 差戻し: 承認者がコメント付きで差戻し。申請は差戻しプールへ入り、誰でも修正・再提出できます
- 部分差戻し: 一部の明細だけを分離してプールへ送り、残りはそのまま進めます（上記「明細ごとの承認と部分差戻し」）
- 却下: 二度と直さない案件を承認者が入口で取消にします（プールに入れず再提出不可）
- 1段リコール: 誤操作のリカバリとして、承認チェーンを1段だけ巻き戻します

## 承認者マスタ

`ApproverMaster` は部署単位、または申請者単位で設定できます。

- `department`: 部署名。全体デフォルトにしたい場合は `*`。
- `applicantEmail`: 空欄なら部署単位ルール。入力すると該当申請者専用ルール。
- `supervisorEmail`: 上席者
- `generalManagerEmail`: 総務部長
- `presidentEmail`: 社長
- `purchasingEmail`: 購買担当

## clasp

このリポジトリは `clasp` 管理を前提にしています。`.clasp.json` は環境固有のためGit管理しません。

```powershell
npm run login
npm run push
npm run open
```

## ローカルチェック

```powershell
npm run check
```

このチェックはGAS実行環境を再現するものではなく、JavaScript構文と主要HTMLファイルの存在確認を行います。実際の動作確認はApps ScriptにpushしてWebアプリ上で行ってください。
