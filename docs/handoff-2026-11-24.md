## 運用で知っておくこと（新しい仕組み）

- **共有キャッシュ**（Storage.gs）: アプリが書き込むとすぐ無効になる。**スプレッドシートを手で直したときだけ最大5分古い表示が残る。**
  すぐ反映したいときは GAS エディタで `clearSharedCache()`（管理者のみ）。Migration.gs の道具を使った後も同様。
- **後回しの仕事**（Jobs.gs）: 書き込み処理は状態を更新したら画面へ返し、PDF とメールは `JOB_*`（ScriptProperties）に積む。
  画面が即時に `runDeferredJobs` で実行し、残りは5分ごとのトリガー `runDeferredJobsSweep` が拾う。
  - 積んだ後に申請の状態・ステップが変わっていたら実行しない（リコール・却下など）。差戻しの一斉共有と分割の通知は出来事の共有なので照合しない。
  - 失敗は再試行しない（二重送信を避ける）。管理者へメール、要点を `JOBFAILED_*` に残す。`listFailedJobs()` / `clearFailedJobs()`。
  - **トリガー `runDeferredJobsSweep` は 2026-11-24 に imaizumi@ で登録済み。** 再登録は `installSyncTriggers`（管理画面の同期ボタンでも可）。
  - 新しく後回しにする関数は `DEFERRABLE_JOBS` に登録し、引数は JSON にできる値だけにする。
- **書き込みのたびに `SpreadsheetApp.flush()` と版数の更新**が入る（共有キャッシュの整合のため）。

## サンドボックス（コピー環境）の作り方（今回の実績）

`docs/testing-on-production.md` の手順に加えて、今回は次で自動化した（コードは repo に入れていない）:
本番スプレッドシートを「コピーを作成」→ コピーの Apps Script を `clasp` で特定（エディタで名前を変えてから URL の scriptId を読む）→
scratchpad に `.clasp.json` を作ってコードを push し、`SandboxSetup.gs` の `sandboxSetup()`（保存先をコピーへ、メールを自分へ寄せる、PDF フォルダを新規）を実行。
コピー直後のスクリプトプロパティは空だった（本番の `DATA_SPREADSHEET_ID` は引き継がれない）。後片付けは `sandboxCleanup()` でゴミ箱へ。
