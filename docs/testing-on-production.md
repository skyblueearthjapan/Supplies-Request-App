# 運用中アプリのテスト手順（周囲に気づかれずに検証する）

このアプリは実運用中で、承認者マスタ・通知宛先マスタには本物のアドレスが入っている。
不用意にテストすると、承認依頼メールや差戻しの一斉共有メールが関係者全員に届く。

## 0. 「気づかれる」経路は4つある

メールを止めるだけでは足りない。

| 経路 | 内容 | 対策 |
|---|---|---|
| **メール** | `MailApp.sendEmail` は4箇所。すべて `sendMail_`（`Email.gs`）経由で、`enableEmailNotifications` の内側にある | リダイレクト（下記2）または `enableEmailNotifications=false` |
| **画面の一覧とバッジ** | ステップ別タブ・全申請は**全アカウントに全件見える**。`getTabCounts` も全体件数を返す | サンドボックスを使う。本番で行うなら滞在時間を最小化する |
| **Drive の PDF** | 承認が進むとPDFフォルダの日付サブフォルダにファイルが増える | サンドボックスでは `pdfFolderId` を空にして別フォルダを作らせる |
| **スプレッドシート** | 申請／申請明細／履歴に行が増える | 同上。本番で行った場合は必ず後始末する |

---

## 1. 推奨：スプレッドシートのコピーでサンドボックスを作る

このアプリはスプレッドシートにバインドされたスクリプトなので、**「コピーを作成」するだけでスクリプトごと複製され、
承認者マスタ・部署別上席マスタ・通知宛先マスタも入った独立環境になる**。
チェックボックスやボタン文言の変化などUIの確認はクリックしないと検証できないため、これが本命。

1. 本番スプレッドシートを **ファイル > コピーを作成**
2. コピーの **拡張機能 > Apps Script** を開く
3. **プロジェクトの設定 > スクリプト プロパティ** に `DATA_SPREADSHEET_ID` = **コピーのスプレッドシートID** を追加
4. コピーの **設定** シートを書き換える
   - `enableEmailNotifications` → `false`
   - `pdfFolderId` → **空欄**
   - `adminEmails` → 自分のアドレスだけ
5. コピーのApps Scriptで **デプロイ > 新しいデプロイ > ウェブアプリ**（実行ユーザー：自分／アクセス：自分のみ）
6. 発行されたURLで自由にテストする
7. 終わったらコピーのスプレッドシートごとゴミ箱へ（バインドされたスクリプトも一緒に消える）

### 飛ばしてはいけない手順

- **手順3を省略すると、アプリが勝手に新しいスプレッドシートを作る。**
  `getSpreadsheet_`（`Storage.gs`）はプロパティ未設定時に `SpreadsheetApp.getActiveSpreadsheet()` へフォールバックするが、
  ウェブアプリ実行では null が返って `SpreadsheetApp.create()` が走る。過去に実際にこれでデータが別シートへ逸れており、
  `Migration.gs` はその復旧のために書かれたもの。
- **手順4の `pdfFolderId` を空にしないと、サンドボックスのPDFが本番のPDFフォルダに混ざる**（設定シートの値はコピーされるため）。
- **手順4の `enableEmailNotifications=false` を先に済ませてから操作を始める。** 承認者マスタには本物のアドレスが入っている。
- コピー側で `setupApplication()` は**実行しない**。日次同期トリガーが二重に作られる。

### サンドボックスでできないこと

外部マスタ（作業員マスタ／DeptApprovers）は `openById` で本番と同じシートを読む。読み取り専用なので影響は無いが、
外部マスタ側を変更するテストはできない。

## 2. 本番で確認したいとき：メールリダイレクト

「本物の宛先に本当に届くか」はサンドボックスでは確認できない。本番で試すときは、
**メールを止めるのではなく自分に寄せる**。GASエディタから実行する。

```js
enableMailRedirect()                       // 自分宛て・120分
enableMailRedirect('you@example.com', 30)  // 宛先と分数を指定
getMailRedirectStatus()                    // 現在の状態を確認
disableMailRedirect()                      // 解除
```

有効な間、アプリが送るすべてのメールは転送先1件だけに届き、件名に `【テスト転送】`、
本文冒頭に**本来の To / Cc** が入る。Cc は落とされ、添付PDFはそのまま転送される。

- **止めるのではなく寄せる理由**：テスト中に本物の申請が動いても通知が失われない。手元に届くので手動転送できる。
- **失効時刻を必ず持つ**：解除し忘れても期限（既定120分）で自動的に無効化される。
  期限の無い値・壊れた値も無効（安全側）に倒す。
- 設定はスクリプトプロパティ `MAIL_REDIRECT_TO`（値は `メール|失効エポックミリ秒`）。
  管理画面には出ないため、他の管理者が誤って触ることはない。

> `MailApp.sendEmail` を新しく追加するときは、**必ず `sendMail_` を経由すること**。
> 直接呼ぶとリダイレクトを素通りして本番の宛先へ飛ぶ。

### 本番で行う場合の追加の注意

一覧とバッジは全員に見えるため、**テスト申請を作ってから消すまでの時間を最小化する**。
UIを手で操作すると数分〜数十分残る。後始末では次の3つを消すこと。

1. テスト申請本体（申請・申請明細・履歴）
2. **分割で生まれた分離先の申請** — `REQ-` 始まりの新規IDになるため、`TEST-` 接頭辞では消えない。
   申請シートの **分離元申請ID** 列でテスト申請を参照している行を探す
3. 生成されたPDF（Driveの日付サブフォルダ）

`SampleData.gs` の `seedExpediteTest()` / `clearExpediteTest()` は、メールを一切送らずに
金額入力待ちの申請を直接シートへ書き込む既存の仕組み。分割のテストにも流用できる。

## 3. 部分差戻し（申請の分割）の確認シナリオ

サンドボックスで、明細4件の申請を作って上席承認まで進めてから：

1. **購買見積で1件のチェックを外して金額確定** — 残り3件の単価だけが保存され、小計・消費税・税込が3件分になる
2. **総務部長ステップで1件外して承認** — 元申請が3明細で次へ進み、分離先がプールに出る。
   **元申請のPDFが3明細に再生成されている**（この遷移は通常PDFを作らないため、分割時だけ明示的に再生成している）
3. **分離先を開く** — 差戻し理由が表示され、「この申請は REQ-… の明細から分離されました」のリンクが出る。
   単位が引き継がれ、単価は未定に戻っている
4. **分離先を再提出** — 上席から通常フローが始まる
5. **全明細のチェックを外す** — ボタンが無効化され、申請全体の差戻しへ誘導される
6. **チェックを外した状態で「差戻し（プールへ）」を押す** — 「選択は反映されず全件が対象になる」旨の確認が出る
7. **2つのタブで同じ申請を開き、片方で明細を修正 → もう片方で分割** — 不一致エラーで中断し、明細も申請も壊れない
8. **明細1件の申請** — チェックボックスが出ない

全項目は `docs/item-level-approval-split-design.md`「7. 検証観点」を参照。
