## 2. 対応した問題：異動者が「申請者」に出てこない

### 症状

今井一也さん（作業員コード 1073）が「製缶・溶接」に異動したのに、新規申請で部署＝製缶・溶接を選んでも申請者の選択肢に出てこない。

### 仕組み（調べて分かったこと）

- 新規申請の **部署** と **申請者** のドロップダウン（`Client.html` の `deptSelectOptions` / `applicantSelectOptions`）は、
  `state.bootstrap.workers` だけから作られる。
- `workers` は `getWorkers_()`（`MasterData.gs`）が **メインDBの「作業員マスタ」シート（キャッシュ）** から読む。
  列は 作業員コード / 氏名 / 部署 / 勤務地 / 区分。
- キャッシュは `syncWorkersMaster()` が外部シートから丸ごと上書きコピーする。
  - 外部シート: `1iu5HoaknlW1W1HheeYv0jqcRq-aY0SyEE2seQd2pHkQ`（「LW／作業日報_全従業員用」）の **作業員マスタタブ（gid 684189184）**
  - 列対応: A=コード, B=氏名, C=部署, E=拠点, F=スタッフ種類
  - 同じ外部ブックの「部署マスタ」タブは**参照していない**。部署の選択肢は作業員の部署列から作られる。
    → **作業員が1人もいない部署は選択肢に出ない。**
- 部署別上席マスタ（DeptApprovers `1Knx_kaQ...`）は承認ルートの解決にだけ使う。申請者の選択肢とは無関係。
- 日次トリガー（毎朝8時台）を作るのは、これまで `setupApplication()` → `ensureMasterSyncTrigger_()` だけだった。

### 原因

- 外部マスタには `1073 / 今井一也 / 製缶・溶接` が入っていたが、アプリのキャッシュは 1072 までで止まっていた。
- GAS の「トリガー」画面が **0件**。直近7日の時間主導の実行も0件。つまり日次同期がずっと動いていなかった。
- エディタで実行すると最初に「承認が必要です」が出て、その後
  `Exception: You do not have permission to call ScriptApp.getProjectTriggers` になった。
  imaizumi@ が `script.scriptapp` スコープを未許可だったのが根本原因と考えられる（いつトリガーが消えたかは不明）。

### 対応

1. GAS エディタ（jev-hands 経由）で `syncWorkersMaster` を手動実行 → `syncWorkersMaster: 50 rows synced`。
   キャッシュに 1073 今井一也 が入ったことを gviz（`.../gviz/tq?tqx=out:html&sheet=作業員マスタ`）で確認。
2. コード変更（`8c7d63e`）:
   - `MasterData.gs`
     - `syncWorkersNow()`：管理者チェック（`assertAdmin_`）→ トリガー自動復旧 → `syncWorkersMaster()`。結果に `triggers` を付けて返す。
     - `installSyncTriggers()`：ScriptLock（`waitLock(30000)`）を取り、`ensureMasterSyncTrigger_` と
       `ensureDeptSupervisorSyncTrigger_` を呼ぶ。**GAS エディタから直接実行してもよい。**
     - `installSyncTriggersSafely_()`：上記を try/catch で包み、失敗しても `{error}` を返すだけにする（同期本体は止めない）。
   - `DeptSupervisors.gs`：`syncDeptSupervisorsNow()` でも同期前に `installSyncTriggersSafely_()` を呼ぶ。
   - `Client.html`：管理画面に「作業員マスタ（外部 作業日報シートと同期・読み取り専用）」カードを追加。
     - ボタン `#syncWorkersBtn`「↻ 外部シートから同期」、件数表示 `#workersSyncInfo`（「毎朝8時台に自動同期」と表示）。
     - `renderWorkersSyncInfo()` / `syncWorkers()`。処理中はボタンを無効化し、終わったら bootstrap を再取得する。
       トースト表示は、エラー / スキップ / トリガー作成失敗 / 成功 で出し分ける。
   - code-reviewer のレビュー結果は APPROVE（指摘は MEDIUM/LOW のみ）。MEDIUM の指摘はすべて反映した:
     トリガー作成を先に呼んで安全ラッパーで包む、クライアントで `result.error` を扱う、ロックとボタン無効化。
3. ユーザー本人が GAS エディタで OAuth 権限を許可 → `installSyncTriggers` を実行。
   トリガー画面が **「Showing 2 triggers」** になった（所有者 Me / Head / 時間主導 / `syncWorkersMaster` と `syncDeptSupervisorsMaster`）。
4. **本番での確認**：社内ポータル（Chrome の履歴にある「LINEWORKS 社内ポータルサイト」）→「貯蔵品購入部品申請」から
   本番 `/exec` を開き、部署＝製缶・溶接を選ぶと申請者に
   タルハ, ラシド, **今井一也**, 佐藤 篤志, 森川 好昭, 鶴田 文明, 萩原 亮 が出ることをスクショで確認。何も送信していない。

## 4. 気になる点（未対応・判断待ち）

優先度の高い順。

1. **トリガーの所有者が imaizumi@ 個人。** トリガーは作成したユーザーの所有になる。imaizumi@ のアカウントが
   停止・権限取り消しになると、日次同期は**また黙って止まる**。失敗通知メールも所有者にしか届かない。
   今回も「いつから止まっていたか」が分からなかった。
2. **トリガーの状態が画面から見えない。** 同期が止まっても誰も気づけない。改善案:
   管理画面に「最終同期日時」と「トリガー登録の有無」を表示する（同期時に ScriptProperties へ最終同期日時を書く）。
   レビューでも LOW 指摘として挙がっていた。未実装。
3. **`syncWorkersMaster` / `syncDeptSupervisorsMaster` は末尾 `_` なしのグローバル関数なので、
   `google.script.run` からドメインの誰でも呼べる**（以前からの仕様）。外部シートを読んでキャッシュを上書きするだけで
   害は小さいが、管理者チェックを入れたいなら `syncWorkersNow` 経由に寄せ、トリガー用は別名にする必要がある
   （トリガーのハンドラ名を変えるなら既存トリガーの作り直しが必要）。
4. **外部マスタの氏名表記ゆれ。** 「今井一也」だけ姓名の間にスペースがない（他は「佐藤 篤志」のように「姓 名」）。
   アプリは氏名をそのまま表示・保存するので、外部の作業日報シート側で「今井 一也」に直すのが良い。ユーザーに提案済み・未対応。
   直すと、既存申請に保存された申請者名（今井一也）と表記が変わる点は注意。
5. **部署名の一致。** 承認ルートは `DeptSupervisors` の部署名と申請の部署名の**完全一致**で決まり、
   一致しなければ `'*'`（全社）→ 承認者マスタにフォールバックする。
   作業員マスタ側で部署名が変わったり新設されたりしたら、DeptApprovers 側にも同じ表記の行があるか確認すること。
   「製缶・溶接」が DeptApprovers にあるかは今回**未確認**。
6. **作業員マスタ・上席マスタのキャッシュ書き込みは `FREE_TEXT_COLUMNS` の保護を通らない**（`setValues` 直書き）。
   作業員コードが `0123` のような形なら数値化される可能性がある（10-17 メモ 3章で「影響小」と判断済みのもの）。
7. **新しい「↻ 外部シートから同期」ボタンは本番でまだ押していない。** 押しても外部シートの内容でキャッシュを上書きするだけ
   （空なら既存を保持）なので安全だが、念のため押す前にユーザーに一声かける。
